# 交付路线

|阶段|依赖|可观察的验收结果|
|---|---|---|
|0 调研|仓库检查|四个市场各自具备原始元数据、访问证据和未知清单|
|1 工程|0|Compose 启动、健康检查、身份认证|
|2 采集|1|带 UTC 接收时间的原始事件可持久化和重放|
|3 模拟 MVP|1、2|从后台建盘，运行基准、守恒对账、暂停恢复|
|4 策略|2、3|决策可定位策略版本和输入事件，缺要素时弃权|
|5 实验|3、4|同流多账户、克隆、配置固定和对照|
|6 回测|2、3、4|固定历史数据、规则、费用和代码可重放|
|7 评估|5、6|成交归因、含成本报告、样本外检验|
|8 改进|7|证据、假设、独立挑战者和人工审核|
|9 运维|1–8|观测、告警、调度、备份和权限可操作|
|10 发布与验证|9|可追踪镜像、恢复演练和独立长期研究结论|

先交付能运行的采集与虚拟账户。正式研究只在数据覆盖、样本量和授权具备后进行。各阶段的实际完成情况以 TASKS.md 的验收记录为准。
