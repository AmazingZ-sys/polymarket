# 访问与凭证

首次启动从本地环境读取管理员口令并持久化 scrypt 摘要；会话使用高熵令牌，数据库仅存哈希。只读用户可用独立环境凭证配置。API 验证来源、角色、结构和速率。生产域名使用 HTTPS 和 Secure cookie。Redis、PostgreSQL 和 worker 使用内部网络，浏览器通过同源代理访问 API。

环境文件及备份仅供部署者读取。Webhook 与 Telegram 凭证仅在服务端。通知失败记录分类和状态码，避免保存含 token 的地址。任何供应商拒绝时记录状态，保留空数据，遵守适用授权及地区条款。数据许可应由部署方逐项确认。

## PostgreSQL 服务权限

Compose 使用专属 PostgreSQL 集群。一次性 migrate 容器和 PostgreSQL 管理进程持有 DDL 凭证，四个服务分别只接收自己的登录口令。本地测试迁移可以完全不配置服务口令，由测试所有者执行。一旦配置其中任意一个服务口令，迁移要求四个都存在，并在迁移完成后对当前数据库重放授权清单。

| 服务角色 | 读取范围 | 可执行写入 |
| --- | --- | --- |
| pq_collector | 市场、规则、费用、事件、来源状态和冷存去重索引 | 行情和结算入库、元数据和来源状态更新 |
| pq_engine | 模拟账户、执行记录、规则、行情和回测状态 | 订单、持仓、账务、研究信号、风险及回测结果 |
| pq_ops | 归档与数据集、运行状态、风险及对账所需数据 | 原包归档、受限账户熔断、报告、通知、计划任务和过期会话清理 |
| pq_api | 管理台展示的数据与应用角色、会话 | 已验证的账户命令、参数和实验配置、审计。会计余额只能经受控函数变动 |

四个角色均无 DDL、角色管理及 users.password_hash 列读取权限。登录时客户端计算 scrypt，数据库按精确用户名检查派生值，返回应用身份。角色无创建业务 schema、写入公共 schema 对象或取得其他运行角色的权限。授权清单显式列出允许访问的业务表及函数。持有定义者权限的函数固定 search_path，公共 schema 禁止普通服务创建对象。[权限清单](../database/runtime-grants.sql)

安装脚本使用操作系统随机数生成服务口令，以权限 0600 原子写入 .env。重复运行可补齐既有部署缺少的环境变量，保留已配置值。从共用角色版本升级时，更新脚本会自动补齐新服务口令。迁移通过 libpq 生成 SCRAM-SHA-256 验证值。只给数据库管理员访问 .env 和备份的权限。

临时升级演练库与还原库共用同一 PostgreSQL 集群的登录角色，授权按数据库生效。升级脚本在临时库重放迁移及授权；在新服务器恢复含 ACL 的备份之前，先用相同部署环境完成一次迁移以建立集群角色。历史行情导入通过 migrate 容器创建新库，ops 角色可导出并校验归档。归档卷和 pg_dump 需配套备份。
