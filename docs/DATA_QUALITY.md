# 数据质量与复查

收到数据时记录 UTC 的 event_time 和 received_at，解析与数据库写入另有 processed_at、persisted_at。供应商无时钟时保留空值或显式标记使用接收时间。engine_events.seq 表示本地追加次序，供应商序号独立保存，未知时为 NULL。采集进程持有独占 advisory lock，使顺序与提交可见性一致。原始载荷和输入规则版本可回溯。

| 检查 | 触发条件 | 后续处理 |
| --- | --- | --- |
| 结构化规则 | 配置 / 币种 / description / 价格源 / token / 时间边界缺失或冲突 | 标记 UNVERIFIED，屏蔽研究交易 |
| 完整性 | WS 断开、进程重启、首次增量先于快照 | GAP，清除受影响的双边书，重连后要求全量快照 |
| 盘口 | 价格或数量非法、买卖交叉、增量顶层不一致 | 原文与原因留痕，清空失效订单簿，重新订阅 |
| 时序 | 来源时间倒退、时钟显著超前、行情过旧 | 保留证据并使匹配失效。迟到数据不得倒写先前状态 |
| 幂等 | 同一市场、来源及同一源事件重复 | 由稳定事件摘要加唯一约束消除重放 |
| 费用 | feeSchedule 缺失、资金模型不支持新指数 | 禁止对该市场进行成本敏感的执行模拟 |
| 结算 | closed 或最终状态缺失，价格非二元，源或 token 对不一致 | 不发兑付事件。新的互斥结果转人工审查 |
| 参考行情 | 外部源不可用、供应商限流 | 保存失败、最后成功时间，保留真实缺口 |

数据集按序号范围归档为压缩 Parquet，保存 SHA-256、行数、首尾序号。源数据、观测前后时间和质量标记一同导出。缺少连续供应商序号时精确丢包率为 UNKNOWN；即使 TCP 未断，也不能对交易所内部的事件完整性作出保证。测试 fixture 与 docs/evidence 中的实测快照仅供核验，在部署时不自动导入业务数据库。

若展示覆盖，以观察到的第一、最后时间以及标记缺口共同解释。连接成功率、最后数据年龄、处理延迟与历史覆盖分别统计；单次握手样本无法证明 24 小时可用性。[现场结果](evidence/2026-11-26/connections.json)

撮合消费的 BOOK 在每个 token 上按 250 ms 发布，完整重同步快照即时发布。未经采样的 WS 消息作为 RAW 保存。每批最多约 64 条派生/原始记录或约 100 ms 后事务提交。崩溃可能丢失尚未提交批次，重启强制 GAP 和重新订阅。首次全量快照之前已进入网络队列的更早增量保留原文，禁止向更晚快照应用。

ops 每十分钟归档，默认给原始包保留至少 24 小时热副本。迁出热库前会再次检查文件 SHA-256 及全部 RAW 的 ID、序号。冷存储按文件保存原包，archived_raw_events 为冷热查询与去重保存索引。目录受损时迁移中止。核对原包可运行 `python -m pqcollector raw --event-id <raw_event_id> --directory /data/parquet`。高频原包冷存以外，标准化快照、索引和 Parquet 均继续增长，备份和容量需覆盖两个数据卷。

现场短时窗口在 2026-11-26 01:44:51–01:45:50 UTC 录得 5,230 条事件，633 个深度图像中 176 个通过采集器质量检查。按市场报文时间与本地接收时间计算，样本 BOOK 延迟中位数为 7.83 秒，P95 为 21.29 秒。撮合还会检查开盘状态、深度、精度和订单到达时效。间断探测共归档 20,198 行，已逐文件验证行数和 SHA-256。此数据量仅供验证吞吐与采集逻辑。[实测与文件清单](evidence/2026-11-26/collector-smoke.json)
